# 声の相棒 2人チームの企画（R18）

最終更新: 2026-10-10 ／ ステータス: 企画中（段3）

この文書が答える問い: 声の相棒を「取り次ぐ山田」と「画面を読む田中さん」の2人チームにするとき、誰が何をし、アプリは何を受け持つか／
何を決めて何が未決か／どう確かめるか。

設計の正本は [マスタープラン R18](universal-io-master-plan.md)、実際の会話で外した例は [事例集](voice-companion-cases.md)、
次の一手は [HANDOFF](../HANDOFF.md) の「声の相棒」節。企画が固まったら、決めたことを R18 へ移す。

## 仕上がりのイメージ（オーナー、2026-10-09）

いまの会話に、もう1人加わる。挨拶をした山田が主に取り次ぐ。ユーザーは誰かに話しかけるのではなく、普通に聞く。
基本は山田が答え、山田は分からないことを田中さんに聞く。**田中さんが調べている間も、山田はユーザーと会話を続けてよい。**

一番便利な使い方は、画面を見ながら自然言語で相談すること（Slack の英語のやりとりを要約してもらい、返信をどう書くか聞く）。
画面の操作の案内も使い方の一つ。ゆくゆくは、書いてもらった文をフォーカス先へ入力したい。

## 3つの役

| 役 | 中身 | 受け持つこと | 受け持たないこと |
|---|---|---|---|
| **山田**（会話担当） | Gemini Live `gemini-3.1-flash-live-preview` | 挨拶、雑談、一般的な知識、ユーザーが口で言った内容の翻訳と下書き、田中さんの答えの取り次ぎ | 画面に何があるか・どこにあるか・何と書いてあるか・目的に着いたかを、自分の推測で答えること。送る・入力するなど、できないことを言うこと |
| **田中さん**（画面を読む役、仮の呼び名） | Gateway `/ai/vision`、`gpt-6-luna` | 画面（スクリーンショットと AX の要素一覧、AX の無いアプリでは画像）を読み、見えたこと・推測・分からないこと・次の一手・目的に着いたかを答える | 会話。ユーザーへ直接話すこと（まずは山田が取り次ぐ） |
| **アプリ**（取り仕切り役＝ハーネス） | macOS クライアント | 田中さんに頼むかを判定する、目的・済んだ手順・いまの画面を覚える、田中さんの答えを会話の切れ目で山田に渡す、古い答えを捨てる、案内した部品が画面にあるかを確かめる、目印を出す | 話すこと |

## 決めたこと

| 日付 | 決めたこと | 理由 |
|---|---|---|
| 2026-10-09 | 会話担当は `gemini-3.1-flash-live-preview` のまま。新しいモデルが出たら試し直す | 3.8 Live は返事の頭の声が化ける（「左側」が「右側」に聞こえる）。3.1 は挨拶・取り次ぎ・次の一歩・雑談のすべてで10回中10回正常で、速さも同じ |
| 2026-10-09 | **非同期はアプリ側で作る。** 山田が田中さんを呼んだら、アプリはすぐ「確認中」と返して山田に会話を続けさせ、田中さんの答えは会話の切れ目にアプリが山田へ渡す | 3.1 はモデル側の非同期（NON_BLOCKING）に未対応で、ツールの答えを返すまで話し始めない（公式文書）。いまの「次の一歩」を渡す仕組み（話していない・聞いていない時だけ送る）がそのまま使える。モデルを替えても使える |
| 2026-10-09 | 田中さんのモデルは `gpt-6-luna`（考える時間は none のまま） | オーナーの指示。low に上げるかは記録の読み直しで決める（効くなら medium も可） |
| 2026-10-09 | 評価は事例集と、記録した田中さんの読み取りの読み直しで行う | 段0（会話の記録）は build 23 で実装済み |

## 提案（オーナーの確認待ち）

調査（段2、要点は HANDOFF）を根拠にした案。

1. **田中さんに頼むかは、山田とアプリの両方が判定する。** 山田が呼ぶか、アプリが文字起こしから画面の質問（「どこ」「どれ」「何て書いてある」「できた？」「この〇〇」）だと判定したら、田中さんを動かす。
   アプリの判定は先回りにもなる（NTT の Ping-Ponder で日本語の待ちが 7.3 秒から 1.0 秒）。会話担当だけに任せると、画面を見ずに言い張る（事例集 B1）
2. **山田が自分で答えてよい範囲を決めて書く（許可リスト）。** 挨拶・雑談・一般知識・ユーザーが言った内容の翻訳と下書き。それ以外の画面の話は必ず田中さんへ。
   あわせて「待つ間に推測で答えない」「できる・できないを仮定しない」を書く（OpenAI chat-supervisor と GPT-Live の指針）。事例集 S1-3・5 の取り違えに効く
3. **声はまず1つ。** 田中さんは声を出さず、山田が「田中さんによると…」と取り次ぐ。2つの声（田中さんが自分の声で話す）は後で比べる。
   大手（ChatGPT Voice、Alexa+）は1つの声で中継し、研究では AI が2人だと成果は同じで混乱が増えた（Chaves & Gerosa 2018）
4. **スキルを作り直す。** 台本型（「〜と言われたら〜を案内」）をやめ、画面や部品ごとの事実、前提条件つきの短い手順、目的に着いたことの見分け方だけを持つ。
   それぞれに画面上の目印（AX の役割とラベル、OCR の文字）を持たせ、**今の画面に当てはまるかはアプリが確かめてから**「見えている／この画面には無い」の印をつけて渡す。
   合わない知識は無いより悪い（MIRAGE 系の研究）。GA4 の「右上の日付」（事例集 G1-1）に効く
5. **田中さんの答えを構造化する。** 見えたこと（根拠つき）／推測／分からないこと／目的の完了条件ごとの証拠／次の一手と対象の参照。
   案内した対象が見えている一覧に無ければ、アプリが言い方を「この画面にはありません」に変えるか、1回だけ差し戻す。証拠の無い完了条件が残る間は「完了」にしない（早すぎる完了は失敗の86%超、VLAA-GUI）
6. **AX の無いアプリには文字認識（Apple Vision の OCR、日本語は accurate モード）と拡大切り出しを足す。** 先に Mac での処理時間を測る

7. **田中さんに状態と計画を持たせる（オーナー案「司令塔」、2026-10-10）。** After Effects（事例集 A1）で、田中さんは「調べた場所と結果」を知らされず、
   目的がアプリのどこにあるかを考える段も無く、2つの設定の節を堂々巡りした。会話担当は取り次いだだけで原因ではない（3.8 に替えても直らない）。
   オーナーの案は「画面には出ないが背後で全部を把握している上司（第3の LLM）」。選択肢は2つ:
   - **A. 田中さんに状態を渡し、計画も答えさせる（1コール）**: 読み取りの依頼に「目的／調べた場所と結果／済んだ手順」を添え、考える時間を low にし、
     「この画面で押す1つ」だけでなく「目的はこのアプリのどこにあるか（この設定の中には無い、閉じて〇〇へ）」も答えさせる。速い。精度は記録の読み直しで測る
   - **B. 別の文字モデルを司令塔にする（2コール）**: 推論ありの文字モデルが目的・履歴・アプリの一般知識から計画を持ち、田中さんは今の画面の読み取り（位置の特定）だけ。
     研究の Talker-Reasoner／Agent S2 の形。確実だが、1手ごとに数秒遅くなり費用も増える
   まず A を記録で試し、足りなければ B、が提案

## 1つの質問が答えになるまで（非同期の流れ）

1. ユーザーが話す。アプリはターンを決め（今まで通り）、文字起こしを見て画面の質問かを判定する。該当すれば田中さんを先に動かす
2. 山田が `look_closely` を呼んだら、アプリはすぐ「田中さんが確認中です。結果が届くまで、画面について推測で答えないでください」と返す。
   山田は「田中さんに確認してもらいますね」と言い、その間もユーザーと話せる
3. 田中さんの答えが届いたら、アプリは新しさを確かめる。話題が変わっていれば、捨てるか、どの質問への答えかを名指しして渡す（未決）
4. ユーザーも山田も話していない切れ目に、アプリが「（田中さんから）言うこと: …」をターンとして送る。山田が取り次ぐ。目印は同時に画面へ
5. 待ちが長いときの途中経過は、決めた秒数で山田が一言言う（未決）

## 確かめたこと

**3.1 でのアプリ側の非同期は成り立つ（2026-10-09、Gemini に直接つないで20回）。** 指示文（persona）を3行直した版で、
「確認中」を返すと山田は約0.7秒で「田中さんに確認してもらいますね。」と一言だけ言い、待つ間の別の質問に普通に答え、画面について推測した回は0。
後から渡した田中さんの答えは「」の名前を一字も変えずに約0.7秒で取り次いだ。直す前の指示文では、確認中の文そのものを読み上げた（3回中2回）。

分かった問題と、アプリでの扱い:

| 問題 | 扱い |
|---|---|
| 話題が変わった後も、古い答えをそのまま取り次ぐ（6回中6回） | 新しい look が来たら、待っている古い答えは捨てる。読み取り中の古い答えも、より新しい読み取りがあれば捨てる |
| 山田が黙って終えたターンには turnComplete が来ない | ターンを送って8秒、声が出ていなければ、次の答えや一歩を送れるようにする |
| 確認中の返答の40〜120ms後に、呼び出し元のターンの turnComplete が来る | 田中さんの答えは5〜7秒後なので、この隙間に送ってしまうことはない |
| 確認中を即座に返すと、呼ぶ前に話していた言葉が途中で切れることがある（2回） | 未対応。実機で目立てば、送る時機を見直す |
| 挨拶に例文が混ざる（17回中1回）、名前の言い違い（25回中1回） | 未対応。事例集で数える |

**build 25 に実装した（Gateway `c9acc06`、実機未確認）。** look には即座に確認中を返し、田中さんの答えは「（田中さんから）」のターンとして
切れ目に送る。つなぎの録音（「確認しますね」）は流さない。

## 未決の論点

| 論点 | 選択肢 |
|---|---|
| 話題が変わった後に届いた答え | 捨てる／「さっきの〇〇ですが」と名指しして渡す |
| 途中経過を言うまでの秒数 | 例: 5 秒（LiveKit の例） |
| 雑談中に田中さんの答えで割り込むか | 割り込まない（切れ目を待つ）／ユーザーが待っている時だけ割り込む |
| 先回りの費用の上限 | 田中さんの読み取り（1回 5〜7 秒）を1分に何回まで許すか |
| スキルを誰が書くか | 人手（AppAgent の研究で成功率 95.6%）／デモを見せて作る（84.4%）／自動の探索（73.3%） |
| アプリ専用の読み取り（例: Blender のアドオンで選択状態を取る） | 個社対応のオプションとして認めるか（ゼロインテグレーションの方針との兼ね合い） |
| 不確かさの伝え方 | 「たぶん」と言う／ユーザーに確認を頼む |
| 評価のラベル付け | オーナーが付けるか |

## 確かめ方（段4）

1. **3.1 でのアプリ側の非同期を、Gemini に直接つないで確かめる**（アプリは触らない。約20回、50円以内）。見ること:
   「確認中」を返した後に山田が自然に話し続けるか／待つ間に画面について推測しないか／後から渡した答えを自然に取り次ぐか／
   話題が変わった後の答えをどう扱うか
2. **田中さんの読み取りを記録から読み直す。** まず40件。指標は「画面に無い対象を案内した率」「次の一手の正解率」「早すぎる完了の率」
   「見えたと言った事実の正解率」「3回の一致度」「待ち」。比べるもの: 考える時間 none／low、スキル なし／いま／条件つき、AX＋画像／画像＋OCR。
   API の費用がかかるので、回す前に回数と金額を伝える
3. **実機で通す。** 決めた流れを入れた build で使い、事例集に足していく
